# PortableStream — сервер (этап 1)

FastAPI-сервер + веб-панель администратора для учебного проекта
PortableStream. Клиент (C++, запускается с флешки) делает скриншот по
кнопке и отправляет его сюда; администратор видит его в панели и может
ответить текстом, который клиент получает в реальном времени по WebSocket.

**Базы данных нет.** Клиенты, скриншоты (метаданные) и сообщения хранятся
в памяти процесса (`app/store.py`). Сами файлы скриншотов лежат на диске
в `data/screenshots/`. После рестарта сервера список клиентов, история
скриншотов и переписка очищаются — для учебного проекта это нормально,
а зато сервер запускается без какой-либо настройки БД.

## Структура

```
app/
  main.py          — точка входа FastAPI
  config.py        — все настройки через переменные окружения
  store.py         — хранилище в памяти: Client, Screenshot, Message
  schemas.py       — Pydantic-схемы запросов/ответов
  auth.py          — проверка admin-ключа и client-токена
  ws_manager.py     — реестр активных WebSocket-соединений
  routers/
    clients.py      — регистрация клиента, heartbeat, список клиентов
    screenshots.py  — загрузка и отдача скриншотов
    messages.py     — переписка администратор <-> клиент
    ws.py           — /ws/admin и /ws/client
static/admin/        — веб-панель администратора (без сборки, просто JS)
render.yaml           — конфигурация деплоя на Render
```

## Как это работает

1. Клиент на флешке один раз регистрируется:
   `POST /api/register {enrollment_key, hardware_id, pc_name}` →
   получает `client_id`, `code` (например `PC-0001`) и свой `token`.
2. Клиент подключается по WebSocket `/ws/client?token=...` (или шлёт
   `POST /api/me/heartbeat`), чтобы считаться «онлайн».
3. По нажатию кнопки «Скрин» клиент шлёт
   `POST /api/me/screenshots` (multipart, файл JPEG/PNG).
   Админ-панель сразу получает уведомление через `/ws/admin`.
4. Администратор пишет ответ в панели →
   `POST /api/admin/clients/{id}/messages` → сервер пушит его клиенту
   по WebSocket, если тот подключён.
5. По нажатию кнопки «Ответ» клиент на всякий случай ещё и спрашивает
   `GET /api/me/messages/latest` — на случай, если WebSocket-пуш не
   дошёл (сон Render, обрыв связи).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `ENROLLMENT_KEY` | Секрет, «зашитый» в конфиг клиента на флешке. Без него никто не зарегистрирует нового клиента. |
| `ADMIN_API_KEY` | Ключ администратора. Вводится один раз в веб-панели (хранится в localStorage браузера). |
| `STORAGE_DIR` | Опционально. Папка для файлов скриншотов (по умолчанию `data/screenshots`). |
| `ONLINE_THRESHOLD_SECONDS` | Через сколько секунд без активности клиент считается офлайн (по умолчанию 90). |

**Обязательно задайте свои значения `ENROLLMENT_KEY` и `ADMIN_API_KEY`**
перед деплоем — значения по умолчанию в коде только для локальной
разработки и предсказуемы.

## Локальный запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ENROLLMENT_KEY=test-enroll
export ADMIN_API_KEY=test-admin
uvicorn app.main:app --reload
```

Панель администратора: http://127.0.0.1:8000/admin
(при первом открытии введите значение `ADMIN_API_KEY`).

## Деплой на Render (бесплатный план)

1. Залейте эту папку в репозиторий на GitHub.
2. На render.com → New → Blueprint → укажите репозиторий (подхватит `render.yaml`),
   либо New → Web Service вручную:
   - Build command: `pip install -r requirements.txt`
   - Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - Health check path: `/healthz`
3. В Environment добавьте `ENROLLMENT_KEY` и `ADMIN_API_KEY` (длинные
   случайные строки, например `python3 -c "import secrets;print(secrets.token_urlsafe(32))"`).
4. Деплой. Панель будет на `https://<ваш-сервис>.onrender.com/admin`.

### Важно про бесплатный план Render

- **Сервис засыпает** после ~15 минут без запросов и просыпается
  10–60 секунд на первый запрос. Клиент и админ-панель уже написаны с
  переподключением, но первый скриншот после «сна» может прийти с
  задержкой — это нормально для бесплатного плана, а не баг.
- **Всё в памяти**: при рестарте/редеплое список клиентов, история
  скриншотов и переписка сбрасываются (клиенты просто зарегистрируются
  заново при следующем запуске с флешки — тот же `hardware_id` получит
  новый `client_id`/`token`). Файлы скриншотов на диске при этом тоже
  эфемерны на бесплатном плане. Для учебной защиты этого достаточно.
